# Диагностика неполадок TutBerry

Команды предназначены для оператора стенда в ~/tutberry. Не выводить секреты и персональные данные в общедоступные журналы.

## 1. API не запускается

Признак: /health недоступен.
Проверить docker compose -f compose.prod.yaml ps, затем docker compose -f compose.prod.yaml logs --tail=50 api. Проверить наличие обязательных переменных, состояние db, миграции и healthcheck. Исправить причину и повторить развёртывание.

## 2. Запущена неверная версия

Признак: /version не совпадает с меткой.
Проверить метку в журнале Deploy, docker compose -f compose.prod.yaml images и APP_VERSION внутри api. Проверить digest в GHCR. Повторить Deploy с правильной меткой; не использовать latest для отката.

## 3. Образ не загружается

Признак: pull завершается ошибкой denied или manifest unknown.
Проверить адрес GHCR, наличие sha-метки, права packages:read и срок действия учётных данных. Повторить вход через защищённый workflow. Не публиковать токен и не отключать проверку TLS.

## 4. Миграции не проходят

Признак: manage.py migrate завершается ошибкой.
Проверить здоровье PostgreSQL, журнал миграции и manage.py showmigrations через compose run --rm --no-deps api. Проверить резервную копию и совместимость схемы. Не удалять том БД; исправить миграцию или согласовать восстановление.

## 5. Уведомления не приходят или поиск устарел

Признак: очередь растёт, письма отсутствуют или результаты поиска устарели.
Проверить docker compose -f compose.prod.yaml logs --tail=50 worker, затем docker compose -f compose.prod.yaml exec broker rabbitmqctl list_queues name messages consumers. Проверить Valkey, Mailpit и DLQ. Восстановить зависимость, повторить обработку согласно async.md. Не очищать весь Valkey.

Статус: инструкция подготовлена по текущей конфигурации; реальные аварийные сценарии стенда не подтверждены.
