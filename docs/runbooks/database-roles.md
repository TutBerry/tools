# Разграничение прав PostgreSQL

Владелец схемы выполняет миграции; отдельная роль tutberry_app используется API и worker. Роль приложения не должна быть владельцем базы, схемы или таблиц и не должна наследовать административные роли.

1. Администратор создаёт LOGIN-роль tutberry_app без SUPERUSER, CREATEDB, CREATEROLE, REPLICATION и BYPASSRLS. Пароль задаётся через защищённый канал, не в Git.
2. Выполнить миграции с DATABASE_URL владельца схемы.
3. Выполнить scripts/grant-runtime-db.sql от владельца таблиц после каждой миграции.
4. Передать API и worker DATABASE_URL ограниченной роли. Не передавать им пароль владельца.
5. Проверить под ролью приложения: SELECT и INSERT в журнал аудита разрешены; UPDATE, DELETE и TRUNCATE запрещены; CREATE TABLE в public запрещён.

Скрипт не меняет существующие данные. На текущем этапе стандартный Compose ещё использует общего пользователя; интеграция ролей и проверка на реальной БД остаются обязательными. Не считать пункты 21–22 аудита закрытыми до успешного теста.
