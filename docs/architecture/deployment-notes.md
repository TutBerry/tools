# Решения по развёртыванию

## Сборка и безопасность

Два этапа Dockerfile: установка зависимостей в venv и копирование окружения в runtime. Alpine выбран после сравнительных проверок Debian: меньше размер и нет обнаруженных HIGH/CRITICAL. Используется pip вместо uv, поскольку проект использует requirements.txt. pip удаляется из runtime venv; системный pip базового образа отдельно не удалялся. apt отсутствует в Alpine; дополнительные системные пакеты не устанавливаются. UID 10001. API и worker используют один образ.

## Среды

Разработка: локальная сборка Compose, учебные пароли, локальные порты Mailpit и панели RabbitMQ. Стенд: готовый образ GHCR, обязательные переменные, ограничения ресурсов, административные порты не опубликованы. В текущем compose.prod.yaml используется management-вариант RabbitMQ без опубликованного порта панели. API доступен на loopback, внешний доступ требует согласованного прокси или туннеля.

## Откат

https://github.com/TutBerry/tools/actions/runs/45458265035 — изолированный smoke успешно переключил две метки одного кода и вернул предыдущую, проверив health/version. Это не доказательство совместимости после изменения схемы. Проверочная миграция, измерение фактического простоя и развёртывание на стенде остаются открытыми. Публикация GHCR и релизные метки настроены только для main, но не проверены фактической публикацией. Слияние не выполнено.
